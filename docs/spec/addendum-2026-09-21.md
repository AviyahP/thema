# `recurrent_dag` — current specification

*21 Sep 2026. **Supersedes `thema-master-spec.md` §10 wherever the two differ.** Written after
measuring the §10 implementation on the real 1,854-pathway build; every change below is a response
to something that measurement showed.*

The differences from §10 are: the full-draw exclusion (step 2), the null read as counts rather than
a maximum (step 7), the re-normalisation in the null, and the twin merge (step 8) — which replaces
the idea that near-duplicate nodes are handled by widening `tol`.

---

## The algorithm

**1. Runs.** 100 runs. Each draws a random 80% of pathways with a hashed per-run seed and runs Ward
on the L2-normalised embeddings.

**2. Groupings.** Every dendrogram node with ≥ 5 members is a grouping, **except the node holding
the run's entire draw**. That node recurs at support 1.0 by construction and says nothing about
which pathways belong together; kept, it reappears as a node holding every pathway — the synthetic
root that `addendum-2026-09-18` A3 removes.

**3. Dedup.** Identical member sets across runs are stored once, remembering which runs produced
them.

**4. Eligibility.** Run *R* can judge grouping *A* if *R* drew ≥ 3 of *A*'s members. *A* is scored
only if ≥ 50 runs can judge it.

**5. Matching.** Let *A_R* be *A*'s members that *R* drew, and *C* the smallest cluster in *R*
containing all of *A_R*. **Extras** are *C*'s members that the origin run *T* also drew but that are
not in *A*; pathways *T* never drew are free and count neither way. *A* is found in *R* if
`extras ≤ tol × |A_R|`.

**6. Support.** `support(A) = runs that found A ÷ runs able to judge A`.

**7. Threshold and null.** Keep groupings with `support ≥ m`; `m` must be below 0.5.

The null permutes each embedding dimension independently across pathways, **re-normalises the rows**,
and runs steps 1–6 with the same seeds. For each `m`, **count** scrambled groupings passing and real
groupings passing. **Never a maximum.**

**8. Twin merge.** Among kept groupings only, in order of support, highest first.

- A pair is **nested twins** if one contains the other and they differ by at most
  `max(2, 10% of the smaller)` members. The higher-support one is the **core**.
- If the twin is the **larger**, each extra member joins the core with
  `inclusion = support(twin) ÷ support(core)`, capped at 1. Where several twins contribute the same
  member, the highest value wins.
- If the twin is the **smaller**, it is simply absorbed.
- The twin is removed after merging.
- Core members keep the inclusion the majority-inclusion step across copies gave them.

**9. Members.** A member is kept if its inclusion is **≥ 0.25**. Every member carries its inclusion
value, and a pathway may be in several nodes with different values.

**10. DAG.** Edges are strict containment on the final member sets, immediate parents only (Hasse).
No synthetic root; the result is a forest. Pathways in no node go to `unplaced`.

## What measurement showed, and what is still open

Measured on the v3 1,854 build, 100 runs, subsample 0.80:

| | |
|---|---|
| pool | 40,775 distinct groupings (real), 43,625 (null) |
| wall time | ~63 s, 75% of it the ancestor walk |
| null groupings reaching m=0.25 | **0**, against 3,457 real |
| null groupings of ≥ 10 members reaching m=0.10 | **0** |

The whole null signal is groupings of 5–9 members: 35 of 43,625 at m=0.10. `3 × max` over that
population gave 0.742, which forced a threshold above the 0.5 ceiling and read as "the method does
not discriminate". Counted instead of maximised, the same data says the opposite.

**Open, to be settled by the tol × m grid on the v4 embeddings:** whether `tol > 0` is needed at all,
which `m` ships, and whether the DAG ships beside `ward_tree`. Placement (70% at tol=0.10, m=0.25)
and post-merge twin rate are the two criteria it has not yet met.
