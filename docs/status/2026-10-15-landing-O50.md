# The O50 ontology and its names on the landing page. 15 Oct 2026

A preview, at `demo/preview-O50/`. **`demo/ontology.js` was not touched** and the default export is
byte-identical. Two things do not work and are reported rather than papered over: the preview is
**104.6 MB**, which is not openable at phone width, and **both example cards no longer hold on this
build**.

## 1. What the exporter gained

| flag | default | effect |
|---|---|---|
| `--build DIR` | none | read the build from any directory, so a **frozen** build works; the `v<version>/<method>` layout stays the default |
| `--names TSV` | none | take names from a naming-c1 table instead of the keyword labels |

A theme shows a real name only when the namer accepted it **and** it is unique. Three kinds keep the
keyword label and the amber chip, and stay distinguishable in the manifest: **declined**,
**colliding**, and **out of naming scope**. The names file and its full sha256 go in the manifest.

**Byte-identity, and the awkward fact behind it.** `export_landing.py` is **not deterministic**: two
runs of the unchanged code produce different bytes, because `sorted()` over a `set` with
case-tied pathway names (`"Gap junction assembly"` against `"gap junction assembly"`) falls back to
set-iteration order, which Python randomises per process. With `PYTHONHASHSEED=0` it is stable, and
under a pinned seed **my change produces byte-identical output to the pre-change code**. That is the
strongest form the guarantee can take. The non-determinism is pre-existing and is **not fixed here**,
because fixing it would change the shipped bytes; a one-line tie-break (`key=(name.lower(), key)`)
would settle it whenever Aviyah wants.

Two more pre-existing things found while checking and deliberately left alone:

- **The documented default invocation fails.** `uv run scripts/export_landing.py` with its default
  `--method ward_tree` raises `KeyError: 'parents'`: `v0.2/ward_tree/nodes.tsv` has no `parents`
  column. The page is in fact generated with `--method recurrent_dag_consensus`.
- **`demo/ontology.js` is no longer reproducible** from the current code and data, even allowing for
  the non-determinism: it is 10,567,043 bytes against 10,571,191 from a fresh run.
- **`prompt_version` is a hardcoded default**, `"v4-repaired"`, used whenever a manifest omits it —
  and `v0.2/recurrent_dag_consensus/manifest.json` omits it, so the published page already states a
  prompt version nothing recorded. The O50 manifest omits it too, so the preview's build line shows
  **the names file and its digest instead**, and the banner never mentions a prompt version.

New manifest keys appear **only** when `--names` is given, so the default payload shape is unchanged.
Collection figures now fall back to the build's own `n` and to `universe.json` beside it — appended
at the end of each lookup chain, so a manifest that already states a figure keeps it.

`tests/test_export_landing.py`, 19 tests: the three name categories, tolerant parsing of
`unnameable`, the four buckets summing to the theme count, provisional nodes keeping a keyword
label, no new manifest keys without `--names`, and the card assertions against the real collection.

## 3. Both example cards: the assertions hold, the clustering claim does not

**Every asserted figure still holds** — `check_cards` passes. Those are gene-level facts read from
`pathways.tsv`: the four NF-kB gene counts (104 / 6 / 46 / 200), the highest pairwise kappa below
0.04, two disjoint pairs; the three insulin gene counts (204 / 167 / 78), the nesting of regulation
inside secretion, and the 21-shared / 57-new overlap. **Nothing was loosened.**

**What fails is the page's claim that those pathways cluster together**, and the two cards fail it
for different reasons:

| card | status on O50 |
|---|---|
| **nfkb** | all four pathways **are** in the build — they sit in 18, 15, 7 and 16 themes — but **no single theme contains all four**. At a 0.50 same-theme cutoff the themes are tighter than the ones that used to hold them together. |
| **insulin** | **none of the three pathways is in the build at all.** O50 is built on universe **L**, the atomic pathways, and all three — `go:GO:0030073`, `go:GO:0050796`, `reactome:R-HSA-422356` — are curated summaries, which L removes by rule. |

The page already renders this honestly: with no containing node it prints *"no single theme contains
all of them"* rather than inventing a theme. The banner now states both reasons explicitly. Both are
pinned by a test, as findings rather than defects.

## 4. The preview, and the size problem

`demo/preview-O50/` holds `ontology.js` (**109,649,823 bytes, 104.6 MB**) and a copy of
`landing.html` (45,262 bytes). **Total 104.6 MB.**

**`ontology.js` is not committed, and cannot be.** 104.6 MB is over GitHub's hard 100 MB per-file
limit, so a commit script naming it would fail at `git push`. It is gitignored and regenerated from
three committed things -- the frozen O50 build, the deduplicated names TSV and
`scripts/export_landing.py` -- by the one command in section 5. `landing.html` **is** committed, so
the banner and the page are reviewable in the diff. That the deliverable does not fit in the
repository is itself part of the finding below.

**That is not openable at phone width, and I did not verify that it is.** I cannot run a browser, so
I checked what is checkable and report the resource facts:

| check | result |
|---|---|
| `ontology.js` parses and sets `window.THEMA_LANDING` | **yes** — 107 ms to read, 436 ms to evaluate in node |
| heap after parsing | **470 MB** |
| `landing.html` loads it with a `<script src>` | yes, and **`fetch(` count is 0**, as decision A1 requires |
| `<meta name="viewport">` and `<meta charset>` | **added to the preview copy** — `demo/landing.html` has **neither**, so its `max-width:760px` and `max-width:980px` rules cannot fire on a phone at all |
| phone media queries present | yes, 760px and 980px |

0.5 s and 470 MB is fine on a laptop and out of reach of a phone tab. **I would not call this
"opens at phone width."**

**The cause, measured.** 98% of the payload is pathway objects: **61,218 of them for 5,539 distinct
pathways**, each appearing 11.1 times on average because a multi-parent theme is emitted under every
parent and carries its members inline each time. Node objects are only 14,524 for 4,339 distinct
themes.

**Capping depth does not fix it** — `MAX_TREE_DEPTH` 4 gives 97.1 MB, 3 gives 85.5 MB, 2 gives
70.1 MB, and 2 already throws away most of the hierarchy.

**What would fix it: emit each pathway object once and reference it by id.** 5,539 objects are 9.2 MB,
plus about 1.5 MB of id references, so the payload lands near **13 MB** — the same order as the
published demo's 10.0 MB. That changes the node shape the page reads, which the exporter's docstring
calls the contract, so it is **a page change as well as an exporter change** and is Aviyah's call.
Nothing was changed here.
